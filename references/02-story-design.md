# 02 設計故事：從觀眾推導，而不是套公式

## 1. 三個前提（沒有答案就問使用者）

| 問題 | 會影響什麼 |
|---|---|
| **觀眾是誰？他們在意什麼？** | 要強調的好處、用詞、技術深度 |
| **看完要做什麼？** | 片尾的行動呼籲、署名方式 |
| **在哪裡播？** | 長度、字幕大小、是否需要無聲也看得懂 |

觀眾 → 在意的事（舉例，不是規則）：

| 觀眾 | 在意 | 不在意 |
|---|---|---|
| 企業決策者 | 成本、風險、導入難度、管理可視性 | 技術細節、框架名稱 |
| 第一線使用者 | 好不好用、省多少時間 | 架構、商業模式 |
| 競賽評審 | 創新性、完成度、社會影響 | 冗長的操作說明 |
| 學生／初學者 | 好玩、看得懂、自己能不能做 | 商業指標 |

## 2. 訊息階層

先寫出來，再談結構：
```
觀眾看完只記得一件事：＿＿＿＿＿＿＿＿（價值主張，一句話）
支撐它的證據（2～4 個，每個要有對應的畫面）：
  1. ＿＿＿＿  ← 鏡頭：＿＿＿＿
  2. ＿＿＿＿  ← 鏡頭：＿＿＿＿
  3. ＿＿＿＿  ← 鏡頭：＿＿＿＿
```
沒有畫面可以支撐的證據，刪掉。

## 3. 選擇敘事結構

| 結構 | 怎麼走 | 適合 |
|---|---|---|
| 問題 → 解法 | 痛點 → 產品登場 → 怎麼解決 → 價值 | 觀眾已經有這個痛（企業、B2B） |
| 成果先行 | 先秀 money shot → 回頭解釋怎麼做到 → 價值 | 視覺很強的產品、注意力短的平台 |
| 前後對比 | 沒有產品的一天 vs 有產品的一天 | 效率類工具 |
| 一個角色的一天 | 跟著使用者完成一個任務 | 流程型系統、使用者是主角 |
| 功能巡禮 | 3～5 個功能，每個一段 | 已經認識產品的觀眾、教學用 |
| 架構解說 | 資料從哪來 → 經過什麼 → 產生什麼 | 技術評審、工程師觀眾 |
| 情境模擬 | 「如果…會怎樣？」連續幾個情境 | 模擬、決策支援、數位孿生 |

可以混用，但整支片要有一條主線。

## 4. 排節奏（beat sheet）

把結構拆成 beat，每個 beat 寫：目的、時長、情緒、畫面、台詞方向。

```
beat  目的          秒數  情緒     畫面                     台詞方向
1     讓觀眾認同痛點  0-10  壓抑     (自己設計)               (自己寫)
2     ...
```

節奏原則：
- **前 3 秒**要有能讓觀眾停下來的東西：痛點、反差、驚人的畫面或數字。
- 情緒要有曲線：壓抑 → 打開 → 推進 → 高點 → 收束。不要從頭到尾同一個強度。
- money shot 放在 2/3 附近，前面要鋪陳。
- 結尾一句話要能被記住；能跟開頭呼應最好。
- 長度參考：中文約 4 字／秒（含停頓），英文約 2.4 字（word）／秒。90 秒 ≈ 330～360 中文字。

長度取捨：時間不夠時，先刪「支撐證據」的數量，不要把每段都壓短。三個講清楚的重點，勝過六個講不清楚的。

## 5. 寫台詞

- 一句一個重點；中文 8～24 字一句，一個 beat 2～3 句。
- 用「你」對觀眾說話；少用「我們將為您介紹」。
- **用畫面演得出來的動詞**：點、切換、新增、下降、亮起。寫完逐句問：「這句的畫面是什麼？」答不出來就改。
- 問句＋答句是展示情境最有力的節奏。
- 數字與縮寫給 TTS 正確念法：`["念法", "字幕顯示"]`，例如 `["C N C", "CNC"]`、`["3 D", "3D"]`。
- 使用觀眾的語言：給台灣觀眾就用台灣用語（影片、資料、軟體、品質、網路、程式、螢幕）。

## 6. 聲音方向

`style` 寫「誰在講、對誰講、什麼口音、什麼速度、什麼情緒」；每場 `dir` 只寫跟平常不同的地方（懸念、轉亮、加重、放慢）。聲音要符合觀眾：給企業的沉穩可信，給學生的可以活潑。

## 7. 誠實原則

| 情況 | 做法 |
|---|---|
| 畫面用模擬資料 | 產品畫面出現期間常駐小字標示；片尾再寫一次 |
| 係數、參數是示範值 | 在出現的地方加註 |
| 功能還沒做 | 只能放在「下一步／路線圖」，用「可串接」「下一步」 |
| 戲劇化的數字（開場帳單金額之類） | 可以，但交付時明確告訴使用者 |
| 客戶、成效、證言 | 沒有真實來源一律不寫 |
| 他人商標 | 不放 |

## 8. 產出

`script.json`（motion-video 格式）。交給使用者確認時，附上每句台詞對應的畫面說明，讓他判斷「這個畫面拍得到嗎」。
