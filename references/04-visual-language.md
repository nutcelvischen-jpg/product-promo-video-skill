# 04 視覺語言：從產品長出來的設計

## 1. 視覺從哪裡來

不要從範本挑顏色。答案在產品裡：

| 從產品取 | 用在影片 |
|---|---|
| 背景色 | 影片底色（再壓暗一點，讓產品畫面浮出來） |
| 主色 | 重點字、強調、光點 |
| 語意色（正常／警告／能源／金錢…） | 標籤、圖例、數字——**意義要跟產品一致** |
| 字型 | 標題與數字（放進 `assets/fonts/` 用 `@font-face`） |
| 圓角、線條粗細、陰影風格 | 卡片、膠囊、框線 |

產品沒有明確設計系統時，從截圖取色（最常出現的背景色、按鈕色、警示色），並跟使用者確認。

在骨架的 `:root` 設定變數：`--bg1/2/3`（背景）、`--cream`（主文字）、`--muted`、`--gold`（runtime 的重點色變數，設成產品主色）、`--glow-rgb`（背景光點）、以及你自己需要的語意色。

## 2. 版面

- 1920×1080；上方 140px 是品牌列（runtime 自動顯示 brand / event），下方 160px 是字幕。內容放中間。
- 畫面同時最多 3 個焦點。新 beat 開始前收掉上一個 beat 的元素。
- 文字壓在產品畫面上**一定要有底**：漸層遮罩、半透明深色卡片、局部壓暗。不要把半透明玻璃壓在亮色 3D 地板上。
- 文字不要壓在產品主體上：放到留白處，或把主體推到另一側（`x` 位移）。
- 字級：大字 120～170px、標題 60～90px、標籤 26～34px、註腳 18～22px。投影或手機上，20px 以下只適合放不重要的註記。

## 3. 技巧工具箱

每個技巧都有它要解決的問題。**先想問題，再挑技巧**；同一招不要每場都用。

| 觀眾的問題 | 技巧 | 做法提示 |
|---|---|---|
| 「我該看哪裡？」 | 推鏡（zoom to point） | 縮放中心設在目標點；在動作發生後 0.3～0.6 秒開始推，1.2～1.8 秒完成 |
| | 局部壓暗／聚光 | 目標以外加深色遮罩或模糊 |
| | 標註（callout） | 線或色條指向目標＋2～6 字標籤；推鏡後再出現 |
| 「這是什麼？」 | 場景標籤 | 小膠囊：類別（小字）＋名稱 |
| | 圖例 | 跟產品語意色一致的小圓點＋名稱 |
| 「它怎麼運作？」 | 公式卡、流程圖、架構圖 | 只放觀眾需要的那一層；元素跟著台詞逐一出現 |
| | 光點／粒子沿路徑流動 | 表示資料或能量的方向（在 `tick()` 依時間計算位置） |
| 「這有多重要？」 | 數字跳動（count up） | 從 0 或從「之前」的值跳到「之後」 |
| | 大字（kinetic type） | 一句話拆 2 行，逐行從模糊浮現；用在金句、轉折 |
| | 暗場 | 把畫面壓暗模糊，讓大字成為唯一焦點 |
| 「這是真的產品嗎？」 | 瀏覽器框 | 第一次秀整個介面時，用傾斜浮入的視窗框 |
| | 真實操作畫面 | 不要用示意圖取代可以拍到的畫面 |
| 情緒轉折 | 圓形展開、閃光、轉場加速 | 用在產品登場、片名、Logo 這種「一次」的時刻 |
| 換話題 | 擦入（wipe）、淡入 | 在下一句開始前 0.3～0.4 秒開始 |

需要表現的東西不在表上？自己設計。原則：動作要有方向與緩動（`expo.out` 進場、`power2.in` 離場）、要在語意上說得通（下降就往下、擴充就展開）、時間要綁台詞。

## 4. 動態原則

- 進場快、離場更快：進場 0.6～1.2 秒，離場 0.4～0.6 秒。
- 一次只動一群東西；多個元素用 stagger 依序出現（0.1～0.4 秒間隔）。
- 靜止超過 3 秒的畫面要有微小的動態（緩慢推近、粒子、光澤掃過），否則看起來像當機。
- 產品畫面本身在動時，疊加的動畫要少。
- 同一支片的轉場語彙要一致：主轉場一種、特殊時刻一種，就夠了。

## 5. 常見技術陷阱

- motion-video 的 `.glass` 自帶 `position:relative`：絕對定位的卡片要加 `position:absolute!important`。
- 沒有 `.abs` class 的容器（自己的大標題、Logo 區）要自己寫 `position:absolute`。
- 渲染環境可能連不到 Google Fonts：字型放本機。
- 不要用 CSS animation／transition、`setTimeout`、`<video>`、`Math.random()`——所有動畫都放 GSAP 時間軸或 `tick(t)`，亂數用 `c.rng(seed)`。
